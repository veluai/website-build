# Backlink playbook

How to keep [the folder](README.md) current. The June 29, 2026 Search Console
pass stays in
[30.45](../30-current-site/30.45-backlink-preservation-audit-2026-06-29.md)
and [30.46](../30-current-site/30.46-backlink-preservation-audit-2026-06-29.csv).

## Two parts

Current state is `80.10`–`80.49`: the audit, the CSV snapshots, the
inventories, the lost-link check, the disavow candidate list, and the gap
notes. Implementation is `80.60`–`80.89`: the backlog, one file per
recommendation, and the log.

A finding in the current-state files becomes a recommendation only when
someone writes a `BL-` item. Implementing that item is a separate step.
Update the item's status and add a log entry when it is done. Do not
implement the next open item in the same change unless Tyler asked for that
item by ID.

## Refresh the current state

1. Pull referring domains, new domains, and lost domains on the same day.
   Record the tool and any overview totals that are not rows.
2. Save three CSVs with LF line endings. The repository whitespace check
   treats a carriage return as trailing whitespace.
3. Write a dated summary. Link the June audit. Do not paste it again.
4. Recount targets, check each distinct velu.us URL, and update the
   broken-target inventory. Mark anything you did not fetch as unverified.
5. If a finding should be acted on, add one recommendation file at the next
   `80.6x` number and a row on
   [80.60](80.60-recommendation-backlog.md). Leave the status open.

## Add a redirect

Velu has no application redirect file. Redirects are GoHighLevel URL rules
for domain `velu.us`.

Before adding a rule:

- The recommendation that calls for it is the one Tyler asked to implement.
- The source returns 404, or a chain that does not already end on the right
  page.
- The destination is a live canonical URL and returns 200. Home is
  `https://velu.us/`. Every other destination has no trailing slash.
- The destination is the page for that service. Current URLs are in
  [30.10](../30-current-site/30.10-current-site-index.md).
- If the URL is a guide or template and no live page is that resource, do not
  redirect it to the homepage. The recommendation is to restore it.
- Do not add a `/wp-content/uploads/` rule. On November 25, 2026 four of those
  rules were stored and the URLs still returned 404, with no
  `x-ghl-serve-region` header. Page-path rules returned 301 with that header.
  The upload rules were deleted the same day.

Enter the rule as domain `velu.us`, path with a leading slash and no trailing
slash, target the full canonical URL, action `url`. Test the slash and
no-slash forms. A working rule is a first response of 301 and a final response
of 200. Record the rule id in the broken-target inventory and in
[80.80](80.80-implementation-log.md).

Rollback is deleting that rule id. Do not delete the June launch rules or the
November 20 `/home` rule while rolling back a later item.

New rules are not appended to
[30.43](../30-current-site/30.43-pre-publication-launch-redirect-map.csv).
Note them in
[30.25](../30-current-site/30.25-gohighlevel-redirect-implementation-checklist.md).

## Disavow

The candidate list stays in current state. Do not upload a disavow file
unless the open recommendation for that upload is the one Tyler asked for.
Google generally ignores the November 25 directory pattern. Monitoring is the
default.

## What not to do

- Do not redirect every old WordPress URL.
- Do not invent a Vercel or framework redirect file.
- Do not invent competitor or directory numbers. If a check was not done,
  write unverified.
- Do not copy client data or credentials into a snapshot.
