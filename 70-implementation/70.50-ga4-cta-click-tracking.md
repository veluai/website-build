# GA4 click events for booking calls to action and service links

**Status:** Prepared November 23, 2026 (America/Chicago). Not saved or
published in GoHighLevel. No GA4, Google Ads, Search Console or HighLevel
setting was changed. The live site is unchanged.

**Source:** [70.50-ga4-cta-click-tracking.html](70.50-ga4-cta-click-tracking.html),
one `<script>` block for the HighLevel Website Settings Head tracking code.

**Authority:** On November 23, 2026 Tyler asked to start tracking clicks on the
"Book Your Discovery Call" / "Get Started" buttons as a GA4 key event, and to
look at the links to the service pages from Home, the service pages and About.
Booking-button clicks become a key event. Service and About link clicks stay
ordinary events so they do not inflate conversions. Publishing the snippet in
GoHighLevel, marking the key event, and registering custom dimensions are
separate steps that each need Tyler's go-ahead. The social-media repository
owns the GA measurement record: its 30.06 playbook and 40.60 implementation
file describe the same events.

## Why

Since property `565314910` started collecting on November 20, 2026 it has
recorded only `page_view`, `session_start`, `first_visit`, `user_engagement`
and `scroll`. The only key events that can fire are the two HighLevel
booking-workflow events (`discovery_call_booked`, `digital_coffee_booked`), so
a week without a booking shows zero key events and no sign of interest that
stopped short of a booking. A click on a booking button is the step just
before the calendar.

## How tracking is wired today

- HighLevel Website Settings, Head tracking code, live-verified on `/` and
  `/get-started` on November 20, 2026: one `gtag.js` loader, then
  `gtag('config','G-9BB7KPXPCQ')` and `gtag('config','G-7LGS60FFST')`, plus
  Clarity. The Body field has the Meta Pixel. See
  [70.30](70.30-appointment-pages-implementation.md).
- The booking events are not page code. Workflows
  `01 Discovery Call - GA4 Booking Event` and
  `02 Digital Coffee - GA4 Booking Event` each send their event to both
  properties through two native HighLevel GA4 actions.
- No page sends a custom click event today. Enhanced measurement can send
  `click` for outbound links only; links between velu.us pages send nothing.
- Clarity has a user-defined "Booking-related button clicks" smart event. It
  is Clarity-only and does not reach GA4.

## Events

The snippet sends each event with `send_to` set to both measurement IDs, so
it reaches the same two properties as the booking workflows.

| Event | Fires when a visitor clicks | GA4 role |
| --- | --- | --- |
| `book_call_click` | A link to `/get-started` (Discovery booking) or `/digital-coffee` (Digital Coffee booking) | Key event on `565314910` after it first appears and Tyler approves the mark |
| `service_link_click` | A link to any `/services/...` page | Ordinary event. Not a key event |
| `about_link_click` | A link to `/about-us` | Ordinary event. Not a key event |

Parameters on every event:

| Parameter | Value | Reportable without setup? |
| --- | --- | --- |
| `link_text` | Visible button or link label, up to 100 characters. HighLevel button microcopy is left out | Yes, GA4's built-in Link text dimension |
| `link_url` | `https://velu.us` + destination path. Query string and fragment are dropped | Yes, built-in Link URL |
| `link_id` | HighLevel element ID, for example `button-iuMhN2l--Cx_btn`. Empty for plain links | Yes, built-in Link ID |
| `link_location` | `header`, `hero`, `section`, `closing` or `footer` | No. Needs an event-scoped custom dimension |
| `booking_type` | `book_call_click` only: `discovery_call` or `digital_coffee` | No. Needs an event-scoped custom dimension |
| `service_slug` | `service_link_click` only, for example `nonprofit-tax-services` | No. Needs an event-scoped custom dimension |

The page where the click happened is GA4's automatic `page_location`, so a
separate `page_path` parameter is not sent. The built-in Page path dimension
works for these events.

`link_location` rules: the shared footer is `footer`; the navigation menu, and
any link in the section that holds it, is `header`; the first section after
the header is `hero`; the last section before the footer is `closing`;
anything else is `section`.

Not counted:

- A link to the page already open, for example the header Get Started button
  on `/get-started`.
- A booking link clicked on `/discovery-call-confirmation` or
  `/digital-coffee-confirmation`. Those visitors have usually just booked.
  Service and About clicks on those pages are still sent.
- Clicks inside the embedded booking calendar. The booking itself stays the
  workflow event.
- The Client Portal, phone, email and legal links.

No form value, name, email address or phone number is read or sent.

## Validation

November 23, 2026, offline. The script was run with jsdom against the saved
live HTML of eleven pages (Home, About, Get Started, Digital Coffee, the four
service pages, both confirmation pages and Privacy Policy) with page scripts
removed and `gtag` replaced by a recorder. Nothing was sent to Google.

- Every covered link produced exactly one event with the expected name,
  `link_location` and `send_to` of both IDs. Totals: 28 `book_call_click`,
  86 `service_link_click`, 20 `about_link_click`.
- Self-links and confirmation-page booking links produced none.
- Loading the script twice did not double-fire.
- A middle-click (`auxclick`, button 1) fired once; a left `auxclick` did not.
- The repository's Python checks include
  `scripts/test_ga4_click_tracking.py`, which checks the measurement IDs, the
  event names and the absence of form or personal-data reads in the source.

Not tested offline: the mobile hamburger menu, which HighLevel renders in the
browser, and real delivery to GA4.

stop at once. Unmark the key event if it was marked. Events already collected
stay in GA4.
